CMS and auction authority

Scope
This guide owns infrastructure, content authority, publication and cost inputs. Creative release decisions belong to docs/administrator-playbook.md; activation and unsupported experiences are listed in docs/launch-readiness.txt. Bid acceptance, receipts, transport and timing are in docs/live-bidding.txt. Retention, archives and disaster recovery are in docs/permanent-provenance.txt.

Stack and data responsibilities
Static React/Vite on Amplify; HTTP API Gateway; ARM Node 22 Lambda; DynamoDB on demand; Cognito identity; SES email. A minute-by-minute EventBridge worker settles auctions and drains the email outbox when enabled. AppSync Events handles live notifications. Services are managed and usage-based, without a dedicated server, VPC, NAT gateway or advertising trackers. Logs retain seven days; customer emails and tokens are not deliberately logged. Restricted SMS delivery logs have the separate contents described in docs/messaging-activation.txt.

Tables: hewge-production stores expiring subscriptions; hewge-auctions stores profiles, releases, bids, transfers, provenance and operational records; hewge-audit is the non-expiring transactional ledger. services/platform.ts is the API/worker entry; services/membership.ts handles email verification and limited preference sessions; services/ownership.ts handles the transfer lifecycle; shared/auction.ts owns public redaction and auction calculations.

CMS responsibilities
- Dashboard > Releases owns the one canonical piece name, story, photos, pricing and dates.
- Dashboard > Pages owns the homepage and editorial pages at /pages/<slug>.
- Text, release records and publication pointers live in DynamoDB. Images and content snapshots live in private, encrypted, versioned S3. Lambda is stateless validation and transaction code, not persistent content storage.
- Page publication takes effect on the next read without rebuilding the application. Private drafts do not replace published pages. Release drafts explicitly remove the piece from public view; publishing a piece page does not enable bidding.
- There is no paid CMS plugin or external auction platform. React/Vite builds the application; GitHub Actions verifies it; the authorised local AWS deployment publishes it to Amplify.

Data and editing
CMS uses strong reads on CMS / LIVE#<id> and DRAFT#<id>. A conditional transaction changes the draft revision and live pointer together with the audit event. Concurrent editors cannot silently overwrite one another. Each save writes a uniquely named S3 snapshot, with its key and hash in the protected audit. Failed saves can leave unreferenced snapshots; these are not publications.
Release pages share AUCTION#<id> / HEAD. The homepage stores its featured release ID, never another copy of the name or price. The stable internal ID toucan-001 is retained for existing references; the public name is After Hours.
Release discovery uses a GSI, then strongly reads each canonical record; a newly created release may briefly be absent from discovery while the index catches up. Homepage lookup is direct and strongly consistent. Bidding and ownership decisions never trust the GSI.
Artwork and page-image URLs are checked against the published record before a short-lived S3 URL is issued. Private evidence cannot be selected as public artwork. Keep unrevealed assets private; a published asset can be copied, and an issued signed URL remains usable for its 60-second lifetime.
Plain text is rendered as text, never executable HTML. Accepted auction terms and privacy versions remain controlled, immutable documents rather than freely mutable CMS copy. Changing contractual rules still requires a versioned application release.

Reveal and media boundaries
Artist/material share draft reveal settings; design has a separate teaser mode. The current binding-auction gate requires artist/material details by opening. Design teasers can withhold name, story and main image before opening. Unpublished drafts are excluded from the public API; unrevealed artist/material fields are redacted and teaser pages omit the design spread. This schema does not implement every administrator-designed sequence; review terms and implement/test unsupported flows before promising them.

Keep unrevealed designs in the studio’s private media library. public/images, client bundles and committed files are publication surfaces. Public image access checks the published release and reveal time; inspection evidence stays private. The homepage showcases the public After Hours design study. Original supplied images and provenance are in assets/; optimised WebP presentation assets are in public/images/. See assets/PROVENANCE.md for the presentation mockup’s limits and docs/branding/concept-brief.txt for fonts/licences.

Costs and capacity
There is no CMS subscription or always-running auction server. A successful bid touches multiple transactional items and protected S3 objects; one bid is not one billable write. Use the load-testing and quota criteria in docs/live-bidding.txt and storage/custody costs in docs/permanent-provenance.txt. The single regional authority pauses writes during regional failure; backups are recovery tools, not automatic regional failover.

Avoid a VPC, NAT, dedicated database instances and multi-region write infrastructure at this scale.

Content initialisation
For an uninitialised content store, use AWS_PROFILE=hewge AWS_REGION=eu-north-1 npx tsx scripts/migrate-content.ts with Node 22. It verifies account 082229154968, copies the public design-study artwork into S3 and seeds the After Hours release/homepage through audited writes. It preserves populated records. scripts/initial-content.ts supplies seed data; live editorial content is managed through the CMS. Do not use initialisation to overwrite CMS edits.
