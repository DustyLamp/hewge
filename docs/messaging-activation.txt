Implemented application flow
- services/sms.ts owns one SMS preference record per verified email, shared across membership links and collector accounts. Contact-only phone fields do not grant SMS consent. Existing unverified preferences can be migrated by explicitly saving the new text settings.
- POST /membership/sms/{preferences,save,request,verify} requires a live verified membership session. POST /me/sms/{preferences,save,request,verify} requires a verified Cognito account. UI: By text in both places; the studio shows SMS consent and number-verification status.
- Codes expire after ten minutes and five attempts. A random 256-bit client-held challenge binds the code hash; neither that raw challenge nor the code is stored in DynamoDB. Atomic revisions and attempt reservations prevent replay and lost updates. Changing or clearing a number invalidates old proof; phone proof expires after 180 days independently of preference renewal.
- SMS opt-out is separate from email. A confirmed leave-all request also disables canonical SMS settings. Number hashes preserve opt-outs after contact expiry; stale consent cannot override them. Profile deletion removes canonical SMS contact data and retains suppression only.
- Runtime flag smsVerificationEnabled enables OTP requests only. The backend checks AWS's account tier; in SANDBOX it sends only to AWS-verified destinations, and currently supports Swiss mobile numbers only. Public release alerts remain inactive.
- SDK automatic retries are disabled. Ambiguous sends stay review-required and consume their budget. Limits: one-minute cooldown, three codes/account/hour, three/number/day, five/IP/day, four globally/day and five globally/calendar month. Each message has a USD 0.15 MaxPrice. These application ceilings do not include earlier console verification messages, taxes or other AWS services; they do not change AWS's USD 1 account spend limit.
- The SMS campaign composer permits 70 plain GSM characters; the server adds HEWGE and a unique unsubscribe URL and enforces a single-part 160-character message. Phone numbers are deduplicated per campaign. Consent and cancellation are checked before queueing and twice around the send claim. Queued release texts expire after one hour. Accepted/uncertain messages are not retried automatically; acceptance is not proof of delivery.
- The hewge-texts configuration set routes TEXT_ALL provider events to /hewge/sms-delivery with seven-day retention. These private operational events contain destination numbers and delivery metadata, not application OTPs or membership tokens. The IAM writer is restricted to this account/configuration set/log group. Inspect final event status, total parts and price for the provider message ID.
- There is no phone number lease or paid verification service. Requests use the existing HEWGE sender, Lambda and DynamoDB. Never raise ceilings or expand countries silently.
