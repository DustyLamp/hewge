Membership and consent lifecycle
Membership begins with an email-only request and a single-use confirmation. After verification, people may add sizes, country/city, bidding interest, name, Instagram and interests. Browser language/time zone are hints, never location facts. Unverified addresses are excluded from size-demand totals as well as mailings. Send verification only while the link is valid and display pending delivery accurately.

The outbox claims each message before sending. Failed or ambiguous sends require inspection rather than automatic duplicate delivery. Release notifications respect consent and size interest; the latest verified membership or collector-account consent wins, including opt-outs. Release mailings require an active verified subscription. Consent is rechecked immediately before delivery. Release email TTL is 30 days. Pending membership requests and verification links expire after 48 hours; confirmed membership records expire after 180 days and expired entries are excluded from the dashboard and campaigns. Preference access uses a separate one-hour opaque session, not bidding/admin credentials. `/membership` provides fresh access links; `/privacy` requests an unsubscribe-only confirmation link. Entering someone else’s email cannot overwrite their preferences or remove their subscription. Each address is limited to four verification requests/hour and each IP to twelve; only hashes of tokens and rate-limit identifiers are stored as lookup keys. Links use URL fragments, cleared on arrival, and are consumed only by explicit confirmation. Transactional outbox text is removed after delivery; all membership outbox records expire after 48 hours.

Confirmed opt-outs also write a non-expiring suppression record containing only the email-address hash and timestamp. Audience preview and the delivery worker check it with strong reads. This prevents expiry of a contact record from reviving an older account opt-in. A later explicit verified opt-in may supersede the timestamp. Account preference saves state the current explicit consent choice; account-profile deletion suppresses older release consent. These suppression records are operational preferences, not permanently locked ownership events.

Transactional winner/receipt notices are independent of marketing consent. Auction/account retention and data-rights requests follow docs/legal-and-card-launch.txt; ownership/security history follows docs/permanent-provenance.txt.

Account verification through Cognito's default email service has a small daily quota; configure SES-backed Cognito email for the planned audience volume.

Application flow
- services/sms.ts owns one SMS preference record per verified email, shared across membership links and collector accounts. A contact-only phone field grants no SMS consent. Text preferences require explicit saving and verification.
- POST /membership/sms/{preferences,save,request,verify} requires a live verified membership session. POST /me/sms/{preferences,save,request,verify} requires a verified Cognito account. The By text controls appear in both places; the studio shows consent and number-verification status.
- Codes expire after ten minutes and five attempts. A random 256-bit client-held challenge binds the code hash; neither the raw challenge nor code is stored in DynamoDB. Atomic revisions and attempt reservations prevent replay and lost updates. Changing or clearing a number invalidates proof; phone proof expires after 180 days independently of preference renewal.
- SMS opt-out is separate from email. Leave-all confirmation disables canonical SMS settings. Number hashes preserve opt-outs after contact expiry; stale consent cannot override them. Profile deletion removes SMS contact data and retains suppression only.
- smsVerificationEnabled enables OTP requests. The backend checks the AWS account tier; in SANDBOX it sends only to AWS-verified Swiss mobile destinations.
- SDK automatic retries are disabled. Ambiguous sends require review and consume their budget. Limits: one-minute cooldown, three codes/account/hour, three/number/day, five/IP/day, four globally/day and five globally/calendar month. Each message has MaxPrice USD 0.15. Application ceilings cover application sends; console messages, taxes and other AWS services have separate costs.
- The campaign composer permits 70 plain GSM characters; the server adds HEWGE and a unique unsubscribe URL and enforces one 160-character GSM-7 part. Numbers are deduplicated per campaign. Consent and cancellation are checked before queueing and around the send claim. Queued release texts expire after one hour. Accepted or uncertain messages are not automatically retried.
- The hewge-texts configuration set routes TEXT_ALL provider events to /hewge/sms-delivery with seven-day retention. The restricted log contains destination numbers and delivery metadata, not application codes or membership tokens. Inspect final status, total parts and price for the message ID. A provider delivery receipt does not prove handset receipt; successful user code confirmation establishes application verification.
