Messages and recipients
The immediate use is user-requested phone-verification codes, sent as TRANSACTIONAL / one-time passwords. Subsequently we plan separately opted-in garment-release announcements, sent as PROMOTIONAL. We do not classify release announcements as transactional. There are no purchased, scraped or imported contact lists, cold messages, affiliate lists or third-party marketing.

People enter their own email first and must verify it before saving text preferences. They then enter their own international phone number and explicitly check an SMS-consent box; a contact-only phone field does not subscribe anyone. A six-digit SMS code must be confirmed before the number is eligible for release alerts. Codes expire after ten minutes and five attempts. Phone proof expires after 180 days. Unverified, expired and opted-out numbers are excluded from campaigns.

Consent text: "Send me Hewge release alerts by SMS when available. I can switch this off anytime."

The opt-in controls appear under "By text" after verified membership access or in the verified collector profile. Public membership email delivery is awaiting a separate SES review; verified collector access is supported by Cognito. We do not claim that the SES request approves SMS.

SMS opt-out is independent of email. Members can disable texts in their preferences, and each promotional text includes its own unguessable unsubscribe link. Opening the link displays a confirmation screen; pressing "Stop text alerts" suppresses the number without requiring sign-in. We retain the phone-number hash and opt-out time so old consent cannot revive messaging. The alphanumeric Swiss sender cannot receive STOP replies, so we do not tell users to reply STOP. They can also contact jez@hewge.design. Consent is rechecked immediately before provider handoff.

Each actual message is restricted to one GSM-7 part. Promotional text plus sender name and generated unsubscribe URL must fit 160 characters. Release dates are individually chosen; there is no promised recurring schedule. A release alert is sent only for an actual release and only to verified, opted-in recipients.

Volume and cost controls
This is a very small initial pilot. The application currently permits at most five SMS sends in total per UTC calendar month, shared between codes and announcements, and at most four globally per day. Each send has MaxPrice USD 0.15. The AWS monthly SMS spend limit remains USD 1. We request production eligibility only, not a spending-quota increase, phone-number lease, dedicated route or broader country coverage. We will review budgets and country requirements deliberately before any larger launch. These application ceilings do not include earlier AWS console verification messages or other AWS services.

Abuse controls include a one-minute resend cooldown, three codes per account per hour, three per number per day, five per source IP per day, atomic attempt limits, origin checks and API throttling. Automatic SMS SDK retries are disabled. Ambiguous sends are held for review rather than automatically repeated. Campaign recipients are deduplicated by phone number; queued announcements expire after one hour.
